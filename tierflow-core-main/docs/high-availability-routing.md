# 高可用路由:多账号负载均衡 · 跨服务商故障切换 · 熔断冷却

本文档说明 TierFlow 如何在上游不稳定或单账号被限流时保持可用率,涵盖三层能力:
同模型多上游、跨渠道自动切换、渠道/账号级熔断冷却。

## 1. 前提:同一模型来自多个上游渠道

路由索引表 `abilities` 以 `(group, model, channel_id)` 为主键。只要**多条渠道在同一
分组下声明支持同一个模型名**,系统就会把它们视为同一模型的多个候选,按「优先级档 → 档内
按权重随机」分流。

配置要点:

- **模型名一致**:客户端请求的逻辑模型名(如 `claude-sonnet`)出现在每条渠道的「模型」列表里。
- **同一分组**:相关渠道挂在同一个 group 下。
- **上游真实模型 id 不同**时,在各渠道用「模型重定向 `model_mapping`」把逻辑名映射到该上游的真实 id,
  对外仍暴露统一逻辑名。

## 2. 单渠道多账号(多 Key)负载均衡

一条渠道可配置多个账号:在渠道 Key 里**按换行分隔**多个密钥,选择轮换模式:

- `random`:每次请求随机选一个可用 Key;
- `polling`:按顺序轮询可用 Key。

每个 Key 有独立健康状态,失败可单独禁用;配合下述熔断,被限流的账号会被**临时冷却**并让
健康账号接量,冷却期满自动恢复。

## 3. 跨渠道故障切换(重试)

`RetryTimes`(系统设置 → 运营设置)控制失败后的跨渠道重试次数,**默认 2**。当某渠道返回可重试
错误时,系统换一条服务同一模型的渠道再试,并**排除本次已失败的渠道**,从而实现「A 家挂 → 自动切
B 家」。

## 4. 熔断冷却(Circuit Breaker)

内存态的熔断器,处理**瞬时故障**(429 限流 / 5xx 抖动),与「自动禁用渠道」互补:

| 机制 | 触发 | 处理 | 恢复 |
|------|------|------|------|
| 自动禁用(已有) | 永久性故障,默认仅 401 | 持久化禁用渠道,写库 | 需健康探测或人工 |
| 熔断冷却(本功能) | 瞬时故障,默认 429 / 500-504 / 520-599 | 内存中临时冷却,从选择中剔除 | 冷却期满自动半开探测,成功即恢复 |

状态机:`Closed`(正常)→ 窗口内失败达阈值 →`Open`(冷却,期间被剔除)→ 冷却期满 →`Half-open`
(放行探测)→ 探测成功回到 `Closed`,失败则重新 `Open` 且冷却时间指数退避(封顶)。

**粒度**:

- 单 Key 渠道:熔断作用于**渠道**,冷却时该渠道被跳过,请求切到其他渠道。
- 多 Key 渠道:熔断作用于**单个 Key**,冷却时该账号被跳过,流量转到同渠道的其他健康账号,渠道本身不受影响。

> 当某档位内所有候选都在冷却时,系统会**放行冷却中的候选**而非直接失败——宁可尝试也不硬失败。

### 配置项(系统设置 → 运营设置 → 高可用路由)

| 键 | 默认 | 含义 |
|----|------|------|
| `RouteBreakerEnabled` | `true` | 熔断总开关 |
| `BreakerKeyLevelEnabled` | `true` | 是否对多 Key 渠道做 Key 级熔断 |
| `BreakerFailureThreshold` | `3` | 窗口内触发跳闸的失败次数 |
| `BreakerWindowSeconds` | `60` | 失败统计滚动窗口(秒) |
| `BreakerCooldownSeconds` | `30` | 基础冷却时间(秒),每次重复跳闸翻倍 |
| `BreakerMaxCooldownSeconds` | `300` | 冷却退避上限(秒) |
| `BreakerTripStatusCodes` | `429,500-504,520-599` | 计为瞬时失败的状态码 |

### 可观测

**路由监控**页新增「渠道健康(熔断)」面板,3 秒轮询实时展示各渠道/Key 的状态
(正常 / 探测中 / 冷却中)、冷却剩余时间、近窗失败数与跳闸次数。对应接口:
`GET /api/route_monitor/health`(管理员鉴权)。

## 关于多实例部署

熔断状态为**每实例内存态**,多实例各自独立熔断(可接受)。如需跨实例共享,可后续接入 Redis;
当前实现预留了扩展点。
